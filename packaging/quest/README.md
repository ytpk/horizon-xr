# Horizon для Meta Quest (OpenXR)

Актуальная инструкция полной сборки, включая Windows/WSL2: [README проекта](../../README.md#build-the-apk).
Из корня проекта: `sh build-apk.sh`; на Windows после настройки WSL2 — `build-apk.cmd`.
Ниже сохранены низкоуровневые команды и заметки раннего этапа; описание офлайн-запуска историческое.
Для входа требуется собственный одобренный application client ID; самосборка его не предоставляет.

Нативный APK (NativeActivity, без Java-кода), который запускает Horizon на Quest 3S / 3 / 2 / Pro
и рисует игру в стерео через OpenXR (Vulkan) с отслеживанием головы и контроллерами Touch.
Вход в аккаунт Microsoft — этап 2 (ниже); сейчас игра идёт офлайн: одиночный мир, LAN и
серверы в offline-mode.

В APK нет файлов Mojang. Ресурсы игры готовятся на компьютере из **вашей** копии
Minecraft: Java Edition 26.3 и копируются на шлем отдельно.

## Что нужно

- Android SDK (`~/Android/Sdk`: build-tools 35, platforms;android-34) и NDK (`~/Android/Sdk/ndk/*`,
  берётся самый новый; другой — через `ANDROID_NDK_HOME`).
- Rust с целью `aarch64-linux-android` (`rustup target add aarch64-linux-android`).
- `zip`, `unzip`, `curl`, `keytool` (JDK), `adb`.
- Шлем в режиме разработчика (Meta Horizon app → Устройства → Режим разработчика), USB-отладка разрешена.

## Сборка

```sh
packaging/quest/build_apk.sh                  # -> target/quest/horizon-quest.apk
NO_AUDIO=1 packaging/quest/build_apk.sh       # без звука (если cpal/AAudio мешает)
SKIP_CARGO=1 packaging/quest/build_apk.sh     # только перепаковать последнюю сборку
DEBUGGABLE=1 packaging/quest/build_apk.sh     # android:debuggable: adb shell run-as (см. ниже)
```

Скрипт собирает `libhorizon_quest.so` (`cargo build --target aarch64-linux-android -p horizon-quest
--profile quest`, API 32), скачивает загрузчик OpenXR от Khronos
(`org.khronos.openxr:openxr_loader_for_android` 1.1.54 с Maven Central, проверка SHA-256, кэш в
`target/quest/cache/`), проверяет, что библиотека зависит только от системных библиотек Quest
(`llvm-readelf -d`) и экспортирует `ANativeActivity_onCreate`, пакует через `aapt2`, выравнивает
`zipalign -P 16` и подписывает отладочным ключом (`target/quest/debug.keystore`, создаётся сам;
свой — через `KEYSTORE=`, пароль `android`).

Чтобы собрать `.so` вручную: `source packaging/quest/env.sh` и обычный `cargo` с
`--target aarch64-linux-android`.

## Ресурсы игры

На компьютере (нужен JDK 25 и серверный jar 26.3 вашей покупки — см. docs/native-client.md):

```sh
cargo run --release -p horizon-prepare -- --prepare --server-jar ~/Downloads/server.jar
cargo run --release -p horizon-prepare -- sounds        # звуки (по желанию)
```

Результат — `.local/horizon-client/26.3`. Затем:

```sh
adb install -r target/quest/horizon-quest.apk          # сначала установка: она создаёт папку приложения
packaging/quest/push_resources.sh                      # -> /sdcard/Android/data/dev.horizon.quest/files/resources
packaging/quest/push_resources.sh /другая/папка/26.3 --launch "--name Steve"
```

Папка приложения на шлеме: `/sdcard/Android/data/dev.horizon.quest/files/`
- `resources/` — подготовленные ресурсы;
- `home/` — данные игры (options.txt, saves/, logs/latest.log, crash-reports/);
- `launch.txt` — необязательные аргументы командной строки, по одному на строку
  (`--name`, `--world`, `--render-distance`, `--server` …), и переменные окружения `ИМЯ=значение`.

`adb uninstall` удаляет эту папку вместе с мирами — сохраните `home/saves` (`adb pull`).

## Запуск и логи

В шлеме: Библиотека → Неизвестные источники → Horizon. Или:

```sh
adb shell am start -n dev.horizon.quest/android.app.NativeActivity
adb logcat -s horizon RustStdoutStderr OpenXR VrApi
adb pull /sdcard/Android/data/dev.horizon.quest/files/home/logs/latest.log
adb shell am force-stop dev.horizon.quest
```

Строка `ИМЯ=значение` в `launch.txt` задаёт переменную окружения:

| Переменная | Что | По умолчанию |
|---|---|---|
| `HORIZON_XR_SCALE` | размер изображения глаза от рекомендованного рантаймом (перекрывает «Разрешение глаза») | из настроек VR: 0.40 (≈1434 px на Quest 3S) |
| `HORIZON_XR_HZ` | частота экрана (`XR_FB_display_refresh_rate`), ближайшая из 72/80/90/120 (перекрывает «Частоту экрана») | из настроек VR: 90 |
| `HORIZON_XR_SNAP` | градусы снап-поворота; `0` — плавный (перекрывает «Поворот») | из настроек VR: 30 |
| `HORIZON_XR_FAKE_HANDS` | `1`: неотслеживаемые контроллеры «держатся» под головой (проверка рук и HUD на руке, когда шлем лежит на столе); `x,y,z,pitch,yaw,roll` — поза правой (левая зеркально), ещё 6 чисел — левая; `file:ПУТЬ` — позы и кнопки (`tl= tr= gl= gr= a=1 b=1 x=1 y=1`) из файла, перечитывается 10 раз в секунду | выкл. |
| `HORIZON_XR_QUIT_AFTER` | секунд до запроса выхода у рантайма (проверка сохранения при Quit) | выкл. |

Остальные настройки шлема — в игре: **Настройки → Настройки Horizon → Настройки VR** (кнопка
есть только со шлемом), файл `home/horizon-vr.txt`.

Пример `launch.txt`:

```
--name
Steve
--render-distance
6
HORIZON_XR_SCALE=0.7
```

Проверка на столе (шлем лежит, контроллеры не в руках): `adb shell am broadcast -a
com.oculus.vrpowermanager.prox_close` держит дисплей включённым (вернуть —
`…automation_disable`). Сокет управления игры (`horizon-ctl`: команды, `give`, `setblock`,
`status`) — TCP-файл в приватной папке приложения: в `launch.txt` строки `--control-socket` и
`/data/user/0/dev.horizon.quest/files/ctl.json`, APK со `DEBUGGABLE=1`, затем
`adb shell run-as dev.horizon.quest cat files/ctl.json` (порт и токен), `adb forward tcp:N tcp:ПОРТ`,
первая строка в сокет — `auth ТОКЕН`. Руки и кнопки — `HORIZON_XR_FAKE_HANDS=file:…/fake.txt` и
`adb push` этого файла.

## Управление

Раскладка и ощущение — как у мода **Visor** (0.6.1): без радиального меню, HUD на голове, хотбар —
колесо на хвате, игровое меню на Y. Основная рука — правая («Левша» в настройках VR меняет стороны).
Источник — `Visor/.../input/actions/*` (привязки Oculus Touch по умолчанию).

| Кнопка | В игре | В меню |
|---|---|---|
| Курок основной руки | атака / ломать (левый клик) | левый клик |
| A | использовать предметом основной руки (правый клик) | правый клик |
| X | использовать предметом второй руки | правый клик (рука, нажавшая курок или X, ведёт курсор) |
| Курок второй руки | как у Visor: действует только на сервере с двуруким режимом (пока нет); в меню — левый клик второй рукой | левый клик |
| B | прыжок | — |
| Y, Menu | игровое меню (вкладки Main / Commands / Tools) | закрыть экран |
| Стик второй руки (левый) | движение: куда смотрит голова; до упора (порог 0.9) — бег; в режиме телепорта вперёд — дуга, отпустить — прыжок в точку | прокрутка |
| Стик основной руки (правый) | снап-поворот 45° (порог 0.5), «Плавно» — плавный | — |
| Клик правого стика | присесть | — |
| Хват основной руки (держать) | колесо хотбара: 9 слотов, центр — слот 0, остальные по часовой от верха; рука отклоняется — слот выбирается, отпустить — закрыть | — |
| Хват второй руки | колесо второй руки (только с двуруким режимом сервера) | — |

Клик мимо экрана в мире закрывает экран (как у Visor). Игровое меню (Y): Main — инвентарь, «Calibrate
Height» (отсчёт 3 с, затем рост = средняя высота головы за секунду), клавиатура, чат, меню паузы,
настройки VR; Commands — режим игры, время, погода; Tools — хитбоксы, границы чанков, перезагрузка
чанков, очистка чата; внизу выход в меню.

Жесты (трекеры по Visor, `TaskSwing`, `TaskRoomSneak`, `TaskRoomJump`, `TaskRoomCrawl`):

| Жест | Что делает |
|---|---|
| Быстрый взмах рукой/инструментом по существу или блоку | удар / удар по блоку (порог скорости 3.0 м/с в настройках «Swing Threshold») |
| Присесть телом: голова ниже 0.85 роста | красться (порог «Sneak Threshold») |
| Ещё ниже, 0.7 роста | ползти (только если сервер разрешил) |
| Подпрыгнуть: голова быстро вверх на 0.1 м и выше 1.05 роста | прыжок (порог «Jump Threshold») |
| Еда у рта | есть / пить |
| Рука у кнопки/рычага/двери + курок | использовать |
| Шаги по комнате | игрок идёт за головой (room scale) |

Рост определяется сам (Auto Height: голова в покое, 90-й процентиль; в чате «Stand up straight for a
moment...» в первый раз), «Measure Now» в настройках VR > VR Body > Height Settings и «Calibrate Height»
в игровом меню замеряют вручную.

Экраны открываются один раз перед вами в 1 м, шириной 1 м (у Visor оверлей шириной в свой масштаб),
и стоят в мире; чат — на 0.5 м выше. Титульный экран — в комнате меню Visor: вы стоите на мшистой
площадке размером с игровую зону над морем облаков, небо идёт по часам (солнце, луна в настоящей фазе,
звёзды ночью, точечная надпись VISOR), панель 2 м шириной на высоте 1.3 м в 1.5 м от центра.
HUD — обычный ванильный, на голове, 1 м шириной, 1.2 м впереди и чуть ниже взгляда; ряда слотов хотбара
в нём нет. Чат и вывод клавиатуры: чат и табличка открывают экранную клавиатуру на панели экрана.
Контроллеры вибрируют при взмахах/ломании/установке, уроне, взрывах, натяжении лука и на колесе хотбара.
Quit в системном меню шлема сохраняет мир (до 15 с), затем приложение закрывается.

### Настройки VR

Настройки → Настройки Horizon → Настройки VR (файл `home/vivecraft-client-config.json`): экран
«VR Settings» устроен как у Visor. Категории в его порядке: Presets, Rendering, VR Body, Controls,
Movement, Immersion, GUI, World; внизу Credits. Названия и подсказки — строки Visor (`visor.options.*`).

| Категория | Что в ней |
|---|---|
| Presets | Defaults, Defaults: Hand HUD |
| Rendering | Render Scale; Effects... > Eye Effects (Health, Hit, Freeze, Pumpkin); «Protocol and Performance...» — Horizon: протокол Visor/Vivecraft, частота, динамическое разрешение, профиль кадра, foveation, маска, хватка потоков |
| VR Body | Select VR Body (Hands Only / Full Body); Height Settings (Height Mode, Units, Auto Height, Measure Now); FBT; Hand Tracking |
| Controls | Left Handed |
| Movement | Movement (Controller / Teleport), Rotation, Rotation Fly, Rotation Step (45°), Smooth rotation, Walk Up, Auto Sprint |
| Immersion | Sneak, Crawl, Climb, Jump, Swim, Dismount vehicle, Boat Rowing, Consume; Advanced: пороги Sneak 0.85, Crawl 0.7, Jump 1.05, Swing 3.0, Swing In Creative |
| GUI | Hotbar... (Center radius 50, Hysteresis 7, Slot numbers), Auto Keyboard, расстояние/размер/прозрачность HUD |
| World | правила мира, который вы создаёте, читаются из `server_settings.yml` (см. примечание на странице) |

Старый файл настроек (до перехода на Visor) один раз приводится к значениям Visor по умолчанию, а его
копия остаётся рядом как `vivecraft-client-config.json.pre-visor`. Ваши рука, режим роста, тип тела,
разрешение глаза и производительность не трогаются.

## Как это устроено

- `crates/horizon-quest` — cdylib `libhorizon_quest.so`: `android_main` (android-activity через
  winit `android-native-activity`), stdout/stderr → logcat (тег `horizon`), папки и аргументы
  (`--home`, `--resources`, `--offscreen`), установка гарнитуры, запуск `entry::main_with` в
  потоке с 64 МиБ стека.
- `crates/horizon-xr` — OpenXR: инстанс с `XR_KHR_vulkan_enable` (+ `XR_KHR_android_create_instance`),
  Vulkan-инстанс и устройство создаёт wgpu-hal с расширениями, которые назвал рантайм
  (`init_with_callback` / `open_with_callback`), на GPU, который назвал рантайм; сессия на очереди
  wgpu; свопчейны глаз и панели меню, обёрнутые в `wgpu::Texture` (`texture_from_raw` +
  `create_texture_from_hal`); цикл кадра; действия Touch.
- `crates/horizon-client-render/src/gfx/headset.rs` — интерфейс `Headset`, `View::eye`
  (асимметричная проекция, reversed-Z: near → 1, far → 0), общий cull-фрустум двух глаз.
  `Renderer::render` при установленной гарнитуре рисует кадр дважды (по проходу на глаз) через
  существующий offscreen-путь прямо в изображения свопчейна, либо один раз — в изображение панели.
- `crates/horizon-client-input/src/headset.rs` — общее состояние «гарнитура ↔ игра»;
  `crates/horizon-client/src/game/headset.rs` — голова поворачивает взгляд игрока от направления
  тела, луч — это мышь на панели меню.
- На десктопе ничего не меняется: без установленной гарнитуры весь новый код спит.

## Решения / Decisions

- **XR_KHR_vulkan_enable (v1), а не enable2.** С v1 Vulkan-инстанс и устройство создаёт сам
  wgpu-hal (его обычный путь, с колбэками на добавление расширений рантайма), так что wgpu
  полностью владеет устройством; с enable2 пришлось бы собирать их через `from_raw` в обход
  проверок wgpu. Quest поддерживает оба расширения.
- **Два прохода, а не multiview.** Каждый глаз — полный кадр рендерера (`ViewSet::eye` с общим
  cull-видом). Просто и совместимо со всеми проходами Horizon; цена — CPU/GPU ×2. Для
  стерео-видов в одном проходе уже есть `ViewSet::stereo` — задел под multiview.
- **sRGB-свопчейн, рисуем через UNORM-вид** (`MUTABLE_FORMAT`): Horizon пишет уже
  sRGB-кодированные значения, как на экране; композитор Quest декодирует sRGB — гамма верная.
- **Пространство LOCAL** и «точка покоя головы»: камера игры = точка покоя, глаза рисуются со
  своими смещениями к ней (наклоны и межзрачковое расстояние видны), при уходе дальше 0.35 м
  точка подтягивается (ходьба по комнате не проносит камеру сквозь стены). Перемещение игрока
  по комнате (roomscale, как в Vivecraft `VRData`) — следующий шаг.
- **Голова = взгляд игрока.** Каждый кадр yaw/pitch игрока подводятся к направлению головы от
  «направления тела» (yaw игрока минус yaw головы); правый стик и сервер поворачивают тело.
  Прицел, атака и установка блоков идут по взгляду (как в seated-режиме Vivecraft), руки пока
  не наводятся контроллерами.
- **Меню на quad-слое**, а не в мире: экран рисуется как на плоском мониторе (1280×720) и
  показывается панелью; луч правого контроллера — это мышь (обычные `CursorMoved`/`MouseInput`),
  поэтому работают все экраны без доработок. За панелью — последний кадр мира (изображения
  глаз не перерисовываются, пока открыт экран).
- **Без покачивания камеры, наклона от урона, тошноты-вращения, эффектов FOV (бег, зелья), TAA
  и генерации кадров** в шлеме: проекция глаза — линза рантайма, поза между проекцией и видом —
  единичная (и для мира, и для руки, и для фрустума заранее собранной геометрии).
- **HUD на своём quad-слое**, а не в изображениях глаз: нарисованный в каждом глазу на одном
  месте, он читался как бесконечно далёкий поверх близких блоков (ощущение «сдвинутого IPD»).
  Кадр мира рисует глаза без HUD, затем HUD — в изображение свопчейна меню (1280×720, игра
  раскладывает HUD под этот размер) на прозрачном фоне; рантайм смешивает его как
  premultiplied alpha (`BLEND_TEXTURE_SOURCE_ALPHA`). Панель «ленивая»: стоит, пока взгляд в
  пределах ~17° от неё (можно опустить глаза на хотбар), и плавно догоняет голову при большем
  повороте (рыскание и тангаж). Прицел на экране убран; виньетка HUD на прозрачной панели
  ничего не делает.
- **Рука от первого лица** рисуется через проекцию глаза (а не плоскую проекцию руки с её FOV) —
  иначе глаза видели бы её на разной «глубине». Она стоит там же, где в ванилле (справа внизу),
  и поворачивается с головой.
- **Разрешение глаза не шире 1440 px.** Quest 3S рекомендует 3586×3586 (вдвое больше панели —
  под суперсэмплинг рантайма); 0.8 от этого, дважды за кадр, держало GPU на 22 FPS.
- **72 Гц явно** (`XR_FB_display_refresh_rate`, после старта сессии) и **sustained high**
  уровни CPU/GPU (`XR_EXT_performance_settings`). Внимание: свойство
  `debug.oculus.refreshRate` (adb `setprop`, до перезагрузки) перекрывает запрос приложения —
  если в `VrApi` видно `FPS=…/120`, проверьте `adb shell getprop debug.oculus.refreshRate`.
- **Кадры темпирует рантайм:** в шлеме не работает ограничитель кадров игры (его AFK-режим
  держал неподвижного игрока на 30 FPS), а рендерер держит на GPU 4 отправки вместо 2 (по одной
  на глаз), так что CPU следующего кадра перекрывается с GPU предыдущего.
- **Снап-поворот 30°** по умолчанию (комфортнее плавного; `HORIZON_XR_SNAP=0` — плавный):
  отклонение стика больше 0.7 поворачивает тело один раз, следующий — после возврата под 0.3.
- **Профиль `quest`** (release без LTO, 16 codegen units): сборка в разы быстрее, чем `release`
  с thin-LTO на всём workspace. Финальные сборки можно делать `PROFILE=release`.
- **Загрузчик OpenXR от Khronos** (Apache-2.0) скачивается при сборке и проверяется по SHA-256,
  в репозиторий не кладётся; он статически слинкован с libc++, `libc++_shared.so` не нужен.
- **Логи:** вместо `android_logger` stdout/stderr перенаправлены в logcat (тег `horizon`): логгер
  Horizon уже печатает свои сообщения в stderr и пишет `latest.log`, второй глобальный логгер
  `log` установить нельзя.
- **Отключено на Android:** `arboard` (буфер обмена — только внутриигровой), раскладко-зависимые
  имена клавиш (`key_without_modifiers` нет в winit для Android), `controllers` (gilrs, DualSense) —
  контроллеры Quest приходят через `headset`. Звук (cpal → AAudio) включён; `NO_AUDIO=1` выключает.
- **Выход:** когда рантайм завершает сессию (Quit в меню шлема), игра запускает своё обычное
  закрывающее сохранение и выходит из цикла, как при закрытии окна; через 15 с процесс
  завершается в любом случае. Проверено `HORIZON_XR_QUIT_AFTER`: `level.dat` записан, процесс
  ушёл за ~3 с.
- **Экран над живым миром** (как GuiHandler Vivecraft): раньше, пока открыт экран, глаза не
  перерисовывались, и рантайм показывал старые изображения в позе головы этого кадра — мир за
  меню «ехал» за головой, отсюда укачивание. Теперь глаза рисуются каждый кадр (`Layers::Screen`),
  а экран — на прозрачной quad-панели, поставленной один раз при открытии. Цена — мир рисуется и
  в меню (как в игре).
- **Прицел от контроллера через поворот игрока:** yaw/pitch игрока следуют лучу основной руки
  (сидя — голове), камера — только голова (`View::eye` от позы глаза). Так все ванильные лучи,
  атаки, снаряды и то, что видит сервер, идут по контроллеру без правок в геймплее; начало луча
  выбора блока/сущности (`Game::aim`) сдвинуто в контроллер. Ходьба стиком поворачивается
  обратно на направление второй руки/головы на стороне OpenXR.
- **Руки как в Vivecraft** (`VRArmRenderer`, `applyFirstPersonItemTransforms`): рамка руки —
  поза aim контроллера (место и поворот, как `getControllerRenderPos`/`getAimRotation`); рука
  игрока со скином (slim/wide) масштаба 0.4 тянется назад от контроллера; предмет — его
  first-person-right-hand трансформ модели, поставленный трансформом Vivecraft своего типа
  (меч/инструмент, блок, факел, еда, удочка, щит, трезубец, копьё, булава, подзорная труба,
  компас, рог, арбалет, лук) — `game/headset_hands.rs`. Gun angle (угол aim к grip, у Touch в
  OpenXR ≈0°, в логе `aim … from its grip`) плюс настройка «Наклон предмета в руке» (40°):
  без него меч и инструменты лежали вдоль предплечья. Карты — как раньше.
- **HUD на запястье** (по умолчанию, как Vivecraft): тот же HUD-слой 1280×720 на панели
  0.6 м (1.5-метровый GUI Vivecraft × 0.4), лежит вдоль предплечья второй руки лицом вверх,
  хотбар над рукой (смещения `GuiHandler` для широкой руки). Основная рука указывает на него
  (до 0.8 м) или касается (6 см) — подсветка слота, курок выбирает слот вместо атаки
  (`InteractiveHotbarModule`). «На руке» — над контроллером, как раньше; прозрачность —
  `XR_KHR_composition_layer_color_scale_bias`.
- **Виньетка комфорта** — quad-слой в пространстве головы (рисует композитор, не наши проходы):
  текстура «прозрачный центр — чёрный край» заливается один раз; сила = настройка × (наклон
  стика ходьбы | плавный поворот | 0.25 с после снап-поворота), чем сильнее — тем меньше квад.
- **Room scale:** смещение головы от точки покоя каждый кадр двигает игрока
  (`MotionWorld::room_step`, `MoverType.PLAYER`, со скольжением вдоль стен), точка покоя
  сдвигается на пройденное, `previous_position` — тоже (камера не дёргается интерполяцией).
  Упёрся в стену — голова может уйти до 0.35 м (как раньше).
- **Жесты** (по трекерам Vivecraft): взмах — скорость кончика (0.3 м от хвата), средняя за
  0.33 с, > 2.5 м/с (в творческом ×1.5); по существу в 1 м (оружие 2 м) от руки — клик атаки,
  один на взмах, любой рукой (клик второй руки прицеливается от неё). Блоки: кончик предмета
  (инструмент 0.35 м, другой предмет 0.1 м, кулак — сама рука) прошёл сквозь блок снаружи —
  атака на этот блок (`forced_hit`) держится 3–7 тиков, а не N вызовов `continueDestroyBlock`
  за тик, как в Vivecraft (не нужен свой пакетный путь, сервер видит обычное копание).
  Касание: рука в блоке с собственным «использованием» (список классов), луч глаз → рука
  попадает в его форму — курок этой руки = «использовать» на нём, атака/использование стиков
  на этот кадр забираются у пада. Еда у рта любой рукой. Вторая рука за плечом → «поменять
  руки» (`BackpackTracker`; основная рука за плечом в Vivecraft меняет слот — не сделано).
  Присед/прыжок — от высоты головы в пространстве LOCAL: рост стоя = самая высокая голова в
  покое (медленно опускается, пока голова рядом), присед — на 0.4 м ниже, прыжок — подъём на
  0.1 м за 0.25 с выше роста на 5 см. Перецентровка сбрасывает рост.
- **Вторая рука как рука:** ванильная логика стреляет/целится по yaw/pitch игрока, поэтому,
  пока действует вторая рука (её курок, её взмах ждёт тика, её предмет в использовании),
  игрок поворачивается по её лучу, а `Game::aim` идёт от неё; «использовать» по курку второй
  руки отдаёт первый ход её предмету (на сервере — `use_item(Off)`). Атака предметом второй
  руки по-прежнему наносит урон предметом основной (ваниль атакует только основной).
- **Лук двумя руками** (`BowTracker`): тетива — 0.198 м над точкой aim второй руки (0.22 роста
  / 2), натяжение до 0.4 м; натяг — правая кнопка мыши, пока держите курок; модель лука —
  стадии по натяжению (как `setItemInUseRemainingClient` Vivecraft), сам лук поворачивается
  вдоль полёта стрелы (`BOW_ROOMSCALE_DRAWING`). Сила стрелы — по времени (ванильный сервер).
- **Радиальное меню** — экран `Screen::Radial` на обычной панели меню (Vivecraft рисует кольцо
  у руки); 8 действий по умолчанию Vivecraft, «камера»/«список игроков»/«факел» заменены на
  «поменять руки», «команда», «достижения».
- **Мир меню:** на титульном экране каждый глаз рисует куб панорамы титульного экрана своей
  проекцией и поворотом (неподвижно — вращение укачивает), за панелью меню.
- **90 Гц по умолчанию:** после исправления звука (ниже) держит 90/90 без пропусков (таблица).
- **Звук на Android:** раз в секунду `SoundEngine.shouldChangeDevice` спрашивал у AAudio список
  устройств — ~45 мс на потоке рендера, 3–4 пропущенных кадра в секунду при любой частоте.
  На Android опрос выключен (AAudio сам следует за системным выходом; потерянный поток
  переоткрывается).
- Код Vivecraft (LGPLv3) не копировался — только идеи (точка покоя/комната, seated-взгляд,
  меню на панели с лучом).

## Риски — проверить на шлеме

- Набор Vulkan-расширений от рантайма и то, что wgpu-hal берёт очередь семейства 0
  (на Adreno это graphics+compute — должно совпасть с требованием OpenXR).
- Формат свопчейна: в логе `Horizon XR: swapchain format …` — ожидается `R8G8B8A8_SRGB` (43).
  Если цвета пересвечены/темны — проверить ветку UNORM и sRGB-вид.
- Раскладка изображений: после кадра изображения переводятся в `COLOR_ATTACHMENT_OPTIMAL`
  пустым проходом рендера; при ошибках валидации — смотреть `finish_headset_images`.
- Reversed-Z и асимметричные фрустумы: шейдеры, которые восстанавливают лучи из NDC по
  `tan_half_fov`/`aspect` (небо, туман, пост-эффекты), считают фрустум симметричным — возможен
  небольшой сдвиг неба/тумана по краям.
- HUD на панели в 1.3 м: блоки ближе 1.3 м всё равно оказываются «за» HUD (как в Vivecraft);
  экранные оверлеи (подводный, огонь, тыква) рисуются в каждом глазу в экранных координатах.
- Производительность (замеры ниже — под водой у берега, дальность 8, глаз 1440²): 64–70 FPS
  при 72 Гц, GPU ~11 мс/кадр (мир ~5.2 мс на глаз + экранный оверлей ~1 мс на глаз), CPU ждёт
  в `xrWaitFrame` ~9.6 мс — упор в GPU. Пропуски кадров видны в логе `VrApi` (`FPS=`), время
  ожиданий OpenXR — в строке `Horizon XR: frames …` каждые 5 с, время проходов на GPU —
  `HORIZON_SHADER_PACK_TIMING=1` в `launch.txt`.

  | Шаг | FPS | GPU, мс (App) |
  |---|---|---|
  | было: глаз 2868², 120 Гц, дальность 12 | 21–22 | 31 |
  | глаз 1440² | 30 | 17–19 |
  | + 72 Гц, sustained high | 30 / 72 | 17–19 |
  | + без ограничителя кадров, 4 отправки на GPU | 51 / 72 | 15 |
  | + дальность 8, симуляция 6, без теней | 64–70 / 72 | 11.4 |
  | (для сравнения: глаз 1280²) | 69–71 / 72 | 10.5 |

  Замеры этого этапа — одно и то же место (джунгли, суша, шлем неподвижно на столе, дальность 8,
  глаз 1434², `VrApi` за 5 с, Stale — пропущенных кадров в секунду):

  | Частота | до (звук опрашивал устройства) | после | GPU App, мс | CPU ждёт в xrWaitFrame, мс |
  |---|---|---|---|---|
  | 72 Гц | 69–71 / 72, Stale 2–4 | 72–73 / 72, Stale 0 | 8.4–8.8 | 10.1 |
  | 90 Гц | 86–88 / 90, Stale 4 | 90–91 / 90, Stale 0 | 7.6 (GPU 599 МГц) | 8.0 |
  | 120 Гц | — | 101–103 / 120, Stale 23–26 | 7.1–7.6 | 6.4 |

  Этап «паритет с Vivecraft» (то же место, руки `HORIZON_XR_FAKE_HANDS=1` с лучами, меткой,
  луком в руке и HUD на запястье): 90 Гц — 90–91 / 90, Stale 0, GPU App 7.9–8.3 мс (было 7.6),
  CPU ждёт в `xrWaitFrame` 7.8 мс (было 8.0) — частота держится, руки/лучи стоят ~0.5 мс GPU.

  120 Гц не держится (кадр CPU ~11 мс: два прохода рендерера по CPU); 90 — держится, это
  значение по умолчанию. Под водой GPU было ~11 мс — там 90 Гц может не держаться: тогда
  «Частота экрана» 72 в настройках VR.
- Память: у Quest 3S 8 ГБ на всё; следить за `horizon-ctl memory`-подобными логами и OOM-killer
  в logcat (`lowmemorykiller`).
- Синхронизация очереди: wgpu и рантайм пользуются одной `VkQueue` из одного потока (submit-поток
  Horizon на Android выключен); если включить `HORIZON_SUBMIT_THREAD=1`, это сломается.
- Жизненный цикл Android (сворачивание, уход в системное меню): сессия переходит в
  STOPPING/IDLE, кадры пропускаются; возврат не проверен.

- Производительность дальше: проходы после мира (экранные эффекты, рука) — отдельные render
  pass'ы с Load/Store всего изображения, на тайловом Adreno это ~1 мс на глаз — слить их с
  проходом мира; общая для глаз CPU-работа (`visibility`, списки секций, загрузки сущностей,
  анимация спрайтов ~0.13 мс GPU на глаз) считается дважды — вынести в общий шаг кадра (это и
  ограничивает 120 Гц); multiview (`ViewSet::stereo`, `VK_KHR_multiview`) вместо двух проходов;
  фовеация (`XR_FB_foveation` + fragment density map — wgpu его не умеет); динамическое
  разрешение. Лучи и метки — линии гизмо (ширина в пикселях): объёмный луч как у Vivecraft.

Этап 2, вход Microsoft (как в QuestCraft):

## Java и подготовка ресурсов на самом шлеме (этап 3 плана docs/quest-launcher-plan.md)

APK несёт всё, чтобы подготовить игру без компьютера, кроме файлов Mojang (их шлем скачивает
сам после входа). В APK:
- `libhorizon_jvm.so` — программа `horizon-jvm` (запускает Java как `java`, но сама грузит
  `libjvm.so`; родной `java` из JDK на Android не находит свой рантайм). Лежит в папке нативных
  библиотек (`extractNativeLibs="true"`), приложение запускает её как дочерний процесс;
- `assets/horizon-jre.zip` — сжатый jlink-образ OpenJDK 25 для aarch64 Android (≈48 МБ на диске,
  ≈30 МБ в архиве; GPLv2 + Classpath Exception, тексты лицензий внутри, `legal/`). Распаковывается
  один раз в папку приложения (`<files>/.../jre`);
- `assets/horizon-bundle.zip` — `research-lock.json`, готовые классы экспортёров (только классы
  Horizon, без кода Mojang) и их исходники, которые хэширует preparer.

```sh
packaging/quest/build_jre.sh      # target/quest/assets/horizon-jre.zip (Termux openjdk-25 + jlink)
packaging/quest/build_bundle.sh   # target/quest/assets/horizon-bundle.zip (нужны импортированные jar 26.3)
packaging/quest/build_apk.sh      # кладёт всё в APK; NO_JRE=1 — без них
```

Проверка на шлеме без моего пакета игры: отдельный id приложения (своя папка данных), в
`launch.txt` строка `HORIZON_QUEST_PROVISION_TEST=run1`. Приложение распакует JRE и бандл,
скачает 26.3 с публичных адресов Mojang (en_us и ru_ru), подготовит ресурсы в
`/data/user/0/<id>/files/provision-test/run1/` и запустит игру на них; ход виден в `adb logcat -s horizon`.

```sh
PACKAGE=dev.horizon.questtest DEBUGGABLE=1 packaging/quest/build_apk.sh
adb install -r target/quest/horizon-quest.apk
# launch.txt должен быть читаем приложением: chmod 644 после adb shell printf (иначе игнорируется)
```
